# Blend profile format (version 1)

A profile tells op2maplib which tiles exist for each ground and how transition
tiles fit together. The library knows nothing about a particular tileset;
everything comes from here. `profiles/op2.json` is the Outpost 2 profile,
generated by `tools/export_op2_profile.py`.

## Top level

| Field | Type | Meaning |
|---|---|---|
| `format` | string | Always `"op2maplib.blend-profile"`. |
| `version` | integer | `1`. The library refuses other versions. |
| `name` | string | Display name. |
| `source` | string | Where the data came from (informational). |
| `tilesets` | string[] | Tileset file names. Tiles refer to them by index. Matched case-insensitively against the map's tileset names. |
| `grounds` | object[] | `{ "id": "mud", "name": "Mud" }`. The order defines ground indices in the API. |
| `pairs` | object[] | `{ "a": "mud", "b": "san" }` for each pair that has transition tiles (informational; the library derives this from `tiles`). |
| `tiles` | object[] | See below. |
| `standardMapping` | `[tileset, image][]` | Optional. A mapping table for maps that use the standard tileset layout. For Outpost 2, all 27 campaign maps share this 2017-entry table. |

## Tiles

Every tile is identified by `ts` (index into `tilesets`) and `img` (image index
within that tileset). The library never uses a map's mapping indices directly.
It matches each map mapping entry to a profile tile by tileset name and image,
so maps with non-standard mapping tables work too.

Common fields:

| Field | Meaning |
|---|---|
| `ts`, `img` | Tileset index and image index. |
| `role` | `"plain"`, `"ground"` or `"transition"`. |
| `w` | Weight: how often the tile is picked relative to the others in the same choice (for Outpost 2, its usage count in the campaign maps). Minimum 1. |
| `cell` | Suggested cell type for the tile, or `null`. Passed through as a number; the library doesn't interpret it. |

**`plain`** has `ground`. A plain-fill tile, used to fill painted areas.

**`ground`** has `ground`. A tile that belongs to a ground but is never placed
by the library: decoration, wreckage, rare tiles. It still tells the library
which ground a cell is when a map is loaded. An unpainted cell holding one keeps
it; painting over it replaces it with fill.

**`transition`** has these fields:

| Field | Meaning |
|---|---|
| `a`, `b` | The two grounds it blends. The tile is placed on cells of ground `a` that border ground `b`. |
| `corners` | Four letters, `a` or `b`, for the corners NW, NE, SE, SW: which ground each corner shows. |
| `edges` | Optional. `{ "n": "aaab", "e": ..., "s": ..., "w": ... }`: each side split into 4 segments. North and south read left to right; east and west read top to bottom. Not used by the version 1 solver; tools and future solvers use it to check seams. |

Tiles not listed at all are unknown to the profile. Cells holding them are
fixed: the library never changes them and ignores them when choosing
neighbours' tiles, until the cell is painted.

## Cliffs (`cliffs`, optional)

Data for drawing cliffs (`om_cliff_draw`). Without this section, the profile
can only blend terrain.

| Field | Meaning |
|---|---|
| `minTiles` | A ground needs at least this many cliff tiles to draw walls (Outpost 2: 40). |
| `fallback` | Cliff family used on grounds without enough cliff tiles of their own (Outpost 2: `"mud"`). |
| `families` | Informational: tiles per family. |
| `tiles` | One entry per cliff tile, see below. Other fields refer to tiles by their position in this list. |

Each cliff tile has:

| Field | Meaning |
|---|---|
| `ts`, `img` | Tileset index and image index. |
| `family` | Ground id the tile belongs to (`"mud"`, `"san"`). |
| `edges` | `"NNNN EEEE SSSS WWWW"`: each side split into 4 segments, `0` = ground, `1` = rock, `2` = either. North and south read left to right; east and west read top to bottom. |
| `inner` | 16 characters, `0`/`1`: the tile's 4x4 rock image, row by row. Optional. |
| `cell` | The tile's usual cell type (cliff high side 9, low side 10, north cliffs 8, ...). |
| `seen` | `{ "n": [...], "e": [...], "s": [...], "w": [...] }`: the tiles seen on that side of this one in the original maps. The solver's strictest stage uses only these pairs. |
| `rims` | `{ "n": hex, ... }`: the 32 RGB pixels along each edge, for scoring how well seams match. Optional. |

The Outpost 2 profile has 156 mud cliff tiles, with edge codes made by hand in
op2-codegen-editor, and 138 sand cliff tiles, generated automatically and
less reliable. Snow has too few tiles, so rock, snow, lava and vegetation use
mud cliffs.

## How the library uses it

A cell of ground A next to a ground B, where (A, B) has transition tiles, gets
a transition tile. Each corner of the cell belongs to B if any of the cells
meeting at that corner is B. That gives a 4-corner key, and the library picks
among the tiles of `(a = A, b = B)` with that key, weighted by `w`. If no tile
has that key, it uses the nearest keys (fewest differing corners). Neighbouring
cells share the corners of their common edge, so their tiles agree there.

## Outpost 2 profile notes

- Grounds: lava, mud, rock, sand, snow and vegetation. Vegetation means tiles
  whose usual cell type is Fast Passable 1.
- Structure tiles (cliffs, walls, tubes, volcanoes, lava flows, bulldozed
  ground and wreckage) are deliberately left out of the profile. That makes
  them fixed: the library never replaces them unless the user paints over
  them. On cm02, that's 4,306 of 65,536 cells.
- Transition pairs: lava/rock, mud/rock, mud/sand and rock/sand, with 48 tiles each.
- Lava and snow have no plain fill tiles, because the campaign maps use too few,
  so they can't be painted with this profile yet.
- In each mud/rock, mud/sand and rock/sand set, every corner key has tiles
  except the two diagonals (NW+SE and NE+SW). Lava/rock lacks three
  single-corner keys.
- The corner letters come from each tile's edge segments. For 114 of the 768
  corners, the two segments meeting at a corner disagreed; the export counts
  those as `b`.
